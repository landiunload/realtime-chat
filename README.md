# Realtime Chat

Чат реального времени на **ASP.NET Core SignalR** с сохранением истории в **PostgreSQL**.
Код организован по принципу **Vertical Slice Architecture** — папки соответствуют возможностям системы, а не техническим слоям.

## Стек технологий

- **.NET 10 / ASP.NET Core SignalR** — двусторонняя связь по WebSocket с автоматическим fallback
- **Entity Framework Core 10 + PostgreSQL** — хранение истории сообщений
- **Serilog** — структурированное логирование
- **xUnit + NSubstitute** — модульные тесты
- **Docker Compose** — локальное окружение

## Ключевые решения

- **Строго типизированный хаб** `Hub<IChatClient>`: контракт клиентских методов описан
  интерфейсом, поэтому опечатка в имени метода — ошибка компиляции, а не молчаливый сбой.
- **Комнаты на группах SignalR**: сообщения доставляются только участникам нужной комнаты.
- **История при входе**: новый участник сразу получает последние 50 сообщений комнаты.
- **Хранилище за интерфейсом** `IChatMessageStore` (инверсия зависимостей):
  PostgreSQL-реализация подменяется в тестах без поднятия базы.
- **Инварианты в модели**: сообщение создаётся только фабричным методом с проверками,
  составной индекс `(RoomName, SentAtUtc, Identifier)` оптимизирует основной сценарий
  чтения вместе с устойчивым тай-брейком истории.
- **Логирование асинхронным стоком**: консольный сток Serilog пишет синхронно и держит
  вызвавший поток, а хаб логирует каждое сообщение. Обёртка `Async` уносит запись на
  фоновый поток — под нагрузкой это ровно вдвое больше пропускной способности
  (замеры ниже) при том же составе лога.

## Запуск

```bash
docker compose up --build
```

Открой `http://localhost:8081` в двух вкладках браузера, войди в одну комнату
под разными именами — сообщения доставляются мгновенно, история сохраняется.

## Тесты

```bash
dotnet test
```

## Пропускная способность

Замер: 30 подключений в одной комнате, 20 отправителей по 200 сообщений,
приложение и PostgreSQL на одной машине, три прогона на конфигурацию.

| Конфигурация логирования | Сообщений в секунду |
| --- | --- |
| Синхронный консольный сток | 1857 / 1876 / 1885 |
| Обёртка `Async` над консолью | 3100 / 3163 / 3382 |
| Логирование на уровне `Warning` (потолок) | 3412 / 3642 / 3789 |

Узкое место — не вставка в PostgreSQL, а синхронная запись в лог: она возвращает
управление хабу уже после того, как сообщение разослано, поэтому доставка выглядела
быстрой, а подтверждение отправителю приходило вдвое медленнее.
